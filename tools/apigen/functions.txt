# Every method the API exposes, over msgpack-RPC or to Lua or both.
# tools/apigen generates the RPC wrapper, the handler table, the `vim.api` Lua
# binding and the api-info metadata from these entries; everything else about
# a wrapper is read off the Rust signature in crates/nvim/src/nvim/api/.
#
#   <name> [flag ...] [key=value ...]
#
# Flags — upstream's FUNC_API_* markers, which the transpile did not carry
# into the Rust tree:
#
#   textlock               refuse while the text is locked
#   textlock_allow_cmdwin  refuse under textlock, tolerate the cmdline window
#   fast                   may run straight from the RPC read callback
#                          instead of being deferred to the main loop. The
#                          Lua binding of a method that is not fast refuses
#                          to run where deferring is unsafe.
#   ret_alloc              the result is heap-allocated for the caller to
#                          free, rather than owned by the request arena
#   remote_only            RPC clients only: the method gets no Lua binding
#   lua_only               Lua only: the method gets no RPC wrapper and no
#                          row in the handler table
#
# Keys:
#
#   argN=<type>  the declared type name of argument N, for parameters whose C
#                declaration carried a decoration Rust cannot express
#                (ArrayOf(Integer, 2) is a plain Array here). It names the
#                type in a "Wrong type for argument N" message, and the
#                metadata publishes it with the decorations that only
#                describe the C side stripped off. Underscores stand for
#                spaces.
#   ret=<type>   the same for the return type, which only the metadata reads.
#   since=<n>    the API level the method appeared at, or -1 for the internal
#                `nvim__*` ones. Required on every nvim_ entry: the metadata
#                publishes it, and results of methods older than API level 11
#                are converted to Lua the pre-0.11 way, which clients depend
#                on.
#   deprecated_since=<n>
#                the API level the method was deprecated at. Metadata only.
#   alias=<name> this method is a deprecated spelling of <name>: it shares
#                that method's wrapper, inherits its fast/ret_alloc, and the
#                metadata describes it with that method's parameters.
#   handler=<p>  the handler is hand-written at crate path <p>.
#
# The deprecated spellings — everything not called nvim_something — were all
# there at API level 0 and all deprecated at level 1, so neither since= nor
# deprecated_since= is spelled out on them.
#
# Entries with alias=, handler= or lua_only get no RPC wrapper of their own.
# The rest are grouped by the API source file, which is also how the
# generated modules are split. Within a group the order is the order upstream
# declared the functions in, which is the order the metadata lists them; the
# emitters sort by name themselves, so nothing else depends on it.
