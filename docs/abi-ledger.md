# The exported ABI

c2rust gave every translation unit's symbols C linkage, so the tree started
with ~6,000 `#[unsafe(no_mangle)] extern "C"` items. Almost none of them had a
consumer that resolved the _name_: the callers were all in-crate, and the
compiler resolves those whatever the mangling. Phase 5c and the phases after it
de-exported the rest, and what is left is small enough to name.

`metrics/abi-ledger.jsonl` is the census, regenerated by `just abi-ledger`
(`--check` fails on drift, and runs in `just minimal-ci`). `scripts/abi-ledger.py`
classifies every export by _who resolves it_:

- **external** — the linked C archives or a dlopened library from the deps
  prefix has it as an undefined symbol. The loader needs the name. **Zero
  today.**
- **test** — `test/unit`, one of the handful of functional specs that
  `ffi.cdef` against the running binary, or `unit-fixtures.so`. The consumer is
  in-repo, so the symbol can be migrated together with the thing that reaches
  it. **All 49 rows.**
- **internal** — nobody resolves the name. Safe to de-export. **Zero today**,
  and `internal_exports` in `metrics/ratchet.json` is the shrink-only number
  that keeps it there.

The ratchet's `no_mangle` count and this file's row count are the same 49. A
new export therefore has to earn its row here.

## Why a row is not free

An exported symbol is a frozen signature and a frozen name. It pins the type
its arguments are spelled in, it survives every rename the module around it
gets, and it keeps a `#[unsafe(no_mangle)]` — an unsafe attribute — in a file
that would otherwise be able to say `#![forbid(unsafe_code)]`. Twelve of the
1,009 `#![allow(unsafe_code)]` files in the tree name their ledger rows as the
reason they cannot.

So the rule is the same one `docs/perimeter.md` applies to unchecked code: a
row stays only while something _outside the crate_ names it, the reason is
written down, and what would retire it is written down with it.

## Adding or removing a row

- `just abi-ledger` regenerates; `just abi-ledger --check` is the gate.
- `check_cdef_declarations` fails the run if a functional spec `ffi.cdef`s a
  crate item that is _not_ exported, because the alternative is an "undefined
  symbol" at runtime in one spec, a long way from the commit that caused it.
- The unit suite is the backstop for the other direction: a symbol that is
  needed and gone makes `cimport` fail loudly on the first spec that wants it.
- A symbol reached by a name the scan cannot see (`lib['mem_' .. name]`) has to
  be listed in `DYNAMIC_SPEC_REFS` by hand. That set is empty today.
